# 21 設計レビュー・対抗的監査（Adversarial Review）

文書ID: REV-001｜版: 0.1.0｜状態: セルフレビューのみ

## 1. 想定攻撃 / 故障シナリオ
- プラグイン切替中に読み書きが重なったら、取りこぼしや二重実行が生じないか。
- `File::sync_all` が失敗した直後に部分レコードが残ったら、次回起動はどうなるか。
- Worker が要求を処理した直後に stdout を失った場合、親は commit 済かを識別できるか。
- manifest の executable を攻撃者が変更したら、署名・権限検証があるか。
- 同一 WAL を 2 つのプロセスが開いた場合、どちらが排他的書込み所有者になるか。
- 断続的に古いバージョンへ戻すと、将来の file format を開けるか。

## 2. 監査結論（初版）
**安全側に失敗する構成の実装見本としては妥当**。ただし、外部 plugin の任意コード実行、双方向 API timeout、multi-process 書込み排他、オンライン migration、ドキュメント JSON validation、網羅的 fuzz、実測性能、正式テスト記録が未了。本パッケージを「完成済みプロダクション DB」と扱ってはいけない。

## 3. 指摘の優先順序
(1) データ破損防止・誤成功 ACK を防ぐ、(2) Worker lifecycle と timeout、(3) SQL parameter binding、(4) 恢復/backup、(5) モデル拡張。これを超える最適化は後回し。
