# 06 プラグイン・マルチモデル設計書

文書ID: PLG-001｜版: 0.1.0｜状態: 未承認

## 1. 原則
モデル、クエリ、索引、ストレージ、同期、AI、セキュリティの**拡張点を定義**する。ただし実稼働 V1 は、in-process Trait + out-of-process Worker の 2 方式のみ。WASM、Native 動的ライブラリ unload、Graph/Vector、cross-engine join は将来計画。

## 2. Plugin 能力マトリクス
| 型 | V1 実装 | 交換対象 | 一貫性境界 |
|---|---|---|---|
| Relational/Turso | 実験 worker | SQL engine | Turso 内 |
| KV | Rust WAL | WAL worker/in-process | 同一 WAL ファイル内の単発操作 |
| Document | Rust WAL（opaque bytes） | WAL worker/in-process | 同上 |
| Graph | 未実装 | graph adapter | V2 定義 |
| Vector | 未実装 | ANN adapter | V2 定義 |
| .NEMA | 未実装 | parser/serializer | V2 定義 |
| Cloud Sync | 未実装 | async sync adapter | V2 定義 |
| Security | 未実装 | permission checks; core enforcement | ネットワーク公開前に必須 |

## 3. プラグイン lifecycle
`discovered → validated → started → healthy → ACTIVE → QUIESCING → retired`。各 route は generation を持つ。旧バージョンの破棄は in-flight 0 後のみ。**子プロセスの強制 kill は再起動可能性と区別する**。

## 4. 互換性レベル
- ABI/IPC レベル: protocol u16 の完全一致（1）。
- セマンティックレベル: DataModel 同一。
- データレベル: storage identity 同一。
- schema / physical format レベル: V1 未検証。これを条件とする無停止データ移行は禁止。

## 5. 管理上の必須制約
- manifest の `executable` は任意バイナリ起動能力を持つ。信頼済み管理者以外に編集を許可しない。
- データ暗号化・プラグイン署名・リソース制限・権限分離は追加設計が必要。
- 汎用 Worker に自動 restart/replay はない。書込み応答消失時は結果不明となり得るため無条件再実行禁止。
- `in-process` プラグインに安全な動的 unload はない。差し替えは Trait Object 参照差し替えに限る。

## 6. 将来の独自エンジンへの差替
V3 では `Engine` と `StorageProvider` を分離し、独自 Page/WAL/MVCC 層を実装。オンライン移行では snapshot, dual-write, CDC fence, commit barrier, validation, rollback を別プロトコルとして追加。
