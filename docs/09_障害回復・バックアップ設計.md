# 09 障害回復・バックアップ設計

文書ID: DR-001｜版: 0.1.0｜状態: 設計、DR 実地試験未実施

## 1. 故障区分と初動
| 故障 | 兆候 | 初動 | 復旧方式 |
|---|---|---|---|
| WAL 末尾欠損 / CRC 不一致 | `Corrupt` | 書込み停止、証跡保全 | 正常な既知 snapshot から復元 |
| Worker EOF | `Plugin` | バイナリ/OS ログ採取 | 管理者が worker を再起動 |
| Swap timeout | `Busy` | 処理排空失敗を調査 | 旧 Engine 継続、後日再試行 |
| Turso DB 異常 | Worker error | Turso 側手順を参照 | Turso のバックアップ・整合性検査 |
| 容量不足 | Io/sync error | 増加停止、空き容量確認 | 書込み結果が不確定なら整合性検査 |

## 2. V1 手動バックアップ
**必ずアプリケーション/Worker を停止してから** WAL/DB をコピーする。オンライン実行中のファイルコピーでは一貫性を保証しない。コピー元ファイルと SHA-256、時刻、作成者、復元試験結果を記録。Turso では DB 以外の WAL 等関連ファイルの取扱いを当該版の公式手順で確認。

## 3. 復元
1. オペレータが障害を記録し停止を宣言する。
2. データディレクトリを read-only で隔離し SHA-256 を記録する。
3. 最終正常バックアップを別ディレクトリに展開する。
4. `polydb get/scan` または SQL SELECT によりレコード件数とサンプルを確認。
5. 監査ログに変更時刻・承認者・影響データを記録し、運用再開。

## 4. 将来実装
V2: snapshot manager、WAL compaction、incremental backup、クラウド暗号化、キー管理、RPO/RTO 測定、定期復旧ドリル。現行 V1 は backup を機能として提供しない。
