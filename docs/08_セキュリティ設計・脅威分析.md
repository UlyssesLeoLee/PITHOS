# 08 セキュリティ設計・脅威分析

文書ID: SEC-001｜版: 0.1.0｜状態: リスク受容未承認

## 1. Trust boundary
`ユーザー CLI → PluginManager → process IPC → third-party binary → data file`。第三者プラグインは管理者の OS 権限で実行される。V1 は isolation by process であって、sandbox/least privilege と同義ではない。

## 2. STRIDE 分析
| ID | 脅威 | 影響 | V1 防御 | 残余リスク |
|---|---|---|---|---|
| TH-01 | なりすまし manifest 編集 | 悪性実行ファイル起動 | 信頼管理者前提 | 高：署名未対応 |
| TH-02 | WAL 改ざん | 読込誤り/破損 | CRC32、fail-closed | 高：CRC は暗号学的認証ではない |
| TH-03 | ユーザ起因 SQL 注入 | 不正 SQL 実行 | ローカル管理者限定 | 高：prepared parameter 未対応 |
| TH-04 | IPC frame resource exhaustion | メモリ浪費 | 8 MiB 制限 | 中：CPU/worker timeout なし |
| TH-05 | data file race | WAL 破損 | 単一 process 運用制約 | 高：OS lock なし |
| TH-06 | Worker 停止/ハング | 処理停止 | エラー検知/子 kill on drop | 高：同期 call timeout なし |
| TH-07 | 未承認外部公開 | 情報漏洩 | サーバ IF なし | 中：後日の誤設定防止が必要 |
| TH-08 | バックアップ漏洩 | 機密情報流出 | cloud sync 未実装 | 高：暗号化・除外ポリシー未実装 |

## 3. Go/No-Go
ネットワーク公開・実顧客データ・高重要度データ利用の前に、署名/ハッシュ検証、OS sandbox、RBAC、transport encryption、at-rest encryption、SQL パラメータ化、操作監査、試験済み backup/restore、IPC timeout、耐障害試験を**必須完了**とする。

## 4. 開発時運用
- data と manifest の write 権限を別管理し、秘密鍵・認証トークンを zip/Git に保存しない。
- 実行バイナリ・依存ライブラリはライセンス/SBOM/脆弱性を継続評価する。
- Fuzz test 対象: WAL replay, IPC decoder, manifest parser, SQL parser boundary。
