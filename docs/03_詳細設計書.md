## 2. Hot Swap 排空と原子切替

```mermaid
sequenceDiagram
    actor Admin
    participant R as Registry
    participant O as Old Engine
    participant N as Candidate
    Admin->>R: hot_swap_with(route, timeout, loader)
    R->>R: transitioning = true
    R->>R: wait(in_flight == 0)
    alt timeout
      R-->>Admin: Busy; old remains
    else drained
      R->>N: loader + descriptor + health
      alt healthy + same model/protocol/storage_id
        R->>R: atomic pointer replace; generation++
        R-->>Admin: next generation
      else rejected
        R->>R: keep Old; transition=false
        R-->>Admin: error
      end
    end
```

### 擬似コード
```text
execute(route, command):
  slot = resolve(route)
  lock(slot); if transitioning: Busy
  in_flight++ ; local_engine = Arc::clone(engine) ; unlock
  defer in_flight-- / notify
  return local_engine.execute(command)

swap(route, loader, deadline):
  lock(slot); transitioning=true
  wait for in_flight=0 or timeout
  unlock; candidate = loader()
  verify protocol==1 && same model && same storage_identity
  candidate.health(); lock(slot)
  if success: engine=candidate; generation++
  transitioning=false; notify; unlock
```
- `loader` panic は `catch_unwind` で捕捉し旧エンジンを維持する（panic=abort や out-of-process crash の扱いは別途検証が必要）。
- ホットスワップは**同一論理データセットへのルート付替え**のみ。オンライン変換・自動 WAL 移行は未実装。

## 3. WAL レコード仕様（V1）
| オフセット | 型 | 内容 |
|---|---|---|
| 0..3 | ASCII[4] | `PDB1` |
| 4..7 | uint32 LE | payload length (最大 4 MiB) |
| 8.. | byte[] | payload |
| 8+n..11+n | uint32 LE | CRC32(payload), polynomial 0xEDB88320 |

payload: `opcode:u8 [1 Put / 2 Delete]`, `namespace_len:u16 LE`, `key_len:u32 LE`, `value_len:u32 LE`, `namespace UTF8`, `key UTF8`, `value bytes`。
**読込**: magic/サイズ/CRC/UTF8/opcode/空 key を検証し、全レコードの再生成功後のみ起動する。破損した末尾を自動切除しない。各 mutation 後 `File::sync_all` し、その後メモリ索引を更新する。
**制限**: 圧縮・ページ管理・B+Tree/LSM・compaction・OS 共有ロック・ファイル間 txn なし。

## 4. IPC v1 詳細
frame: `payload_size:u32 LE`→`protocol:u16 LE=1`→`opcode:u8`→`argc:u8`→`(length:u32 LE, raw bytes)×argc`。最大 frame 8 MiB。

| opcode | 方向 | 引数 | 応答 |
|---|---|---|---|
| 1 PING | request | - | 100 OK,0 args |
| 2 PUT | request | ns,key,value | OK |
| 3 GET | request | ns,key | OK,value / 102 NONE |
| 4 DELETE | request | ns,key | OK |
| 5 SCAN | request | ns,prefix | OK,key/value pairs |
| 6 SQL_EXEC | request | sql | OK |
| 7 SQL_QUERY | request | sql | OK,utf8 result |
| 100 OK | response | depends | - |
| 101 ERROR | response | error utf8 | - |
| 102 NONE | response | - | - |

プロトコル mismatch / 欠損 / 不正 UTF8 はエラー。IPC は認証・暗号化を提供せず、公開ネットワークで使用不可。SQL Query V1 返却は JSON envelope だが各 cell は Debug 文字列化であり厳密な型付返却ではない。

## 5. manifest 詳細
形式はコメント (`#`) と `key=value`。必須: `name`, `protocol=1`, `model`, `executable`, `dataset`。重複・未知キーは拒否。対応モデル `kv`, `document`, `relational`。path の署名・サンドボックス・相対パス整合は未実装のため、**信頼済みの管理者が配置した構成のみ**利用可能。

## 6. 例外管理
| エラー | 発生条件 | 動作 |
|---|---|---|
| Invalid | 空キー、長さ超過、manifest 形式 | 入力拒否 |
| Busy | 切替中、排空期限切れ | ルートを維持してリトライ可 |
| Incompatible | protocol/model/dataset 不一致 | 旧プラグイン維持 |
| Corrupt | WAL 破損/切断 | 起動失敗、手動復旧 |
| Plugin | 子プロセス障害・異常 Reply | 不可逆な自動再送はしない |
| Unsupported | 未実装の Graph/Vector/SQL 操作 | 明示拒否 |

## 7. データ型対応
`namespace` と `key` は空でない UTF8、`value` は任意 bytes、サイズはレコード合計 4 MiB 以下。Document payload の JSON 構文妥当性は V1 では検証しない。
