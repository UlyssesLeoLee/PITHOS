# 05 インタフェース設計書（Rust API / IPC / SQL Worker）

文書ID: IFD-001｜版: 0.1.0｜状態: 未承認

## 1. 公開 Rust IF
```rust
trait Engine: Send + Sync {
    fn descriptor(&self) -> Descriptor;
    fn execute(&self, command: Command) -> Result<Response>;
    fn health(&self) -> Result<()>;
}

// data-plane
manager.execute("kv", Command::Get {namespace:"main".into(), key:"id".into()})?;
// control-plane
manager.hot_swap_with("kv", Duration::from_secs(5), || Ok(new_engine))?;
```
API は同期・単一呼出しを基本とする。Worker IPC 側は同一ワーカに対して Mutex による逐次化。高並列・非同期 SQL への実装改修は V2。

## 2. API コマンド契約
| Command | Model | 入力検証 | 結果 |
|---|---|---|---|
| Put | KV/Document | non-empty ns/key, max 4 MiB | Ack |
| Get | KV/Document | non-empty key（Get は現状空文字も探索可能） | Value(Some/None) |
| Delete | KV/Document | non-empty ns/key | Ack |
| Scan | KV/Document | prefix arbitrary UTF8 | Items sorted by key |
| SqlExec | Relational | 管理者のみ | Ack |
| SqlQuery | Relational | 管理者のみ | Text(JSON, cell Debug String) |
| Ping | all | - | Ack |

## 3. CLI 操作
```
cargo run --bin polydb -- demo ./data
cargo run --bin polydb -- put ./data kv app user:1 alice
cargo run --bin polydb -- get ./data kv app user:1
cargo run --bin polydb -- put ./data document app doc:1 '{"ok":true}'
cargo run --bin polydb -- scan ./data kv app user:
```
Process Worker: `cargo build --bins` 後 `polydb process-demo ./target/debug/polydb-worker ./data`。Windows の exe 名は `.exe`。

## 4. Turso アダプタ実行例
```
cargo build --manifest-path adapters/turso-worker/Cargo.toml
cargo run --bin polydb -- sql-exec ./adapters/turso-worker/target/debug/polydb-turso-worker ./data/demo.db "CREATE TABLE IF NOT EXISTS t (id INTEGER PRIMARY KEY, name TEXT)"
cargo run --bin polydb -- sql-query ./adapters/turso-worker/target/debug/polydb-turso-worker ./data/demo.db "SELECT * FROM t"
```
SQL を受け取る前に `data/` を作成する。**SQL はプレースホルダ未対応・trusted CLI 専用。アプリ入力を SQL に連結して渡してはならない。**

## 5. IF エラーモデル
`Result<Response,DbError>` を標準とし、`Not Found` は Get の `Response::Value(None)`。切替中の新規操作は `Busy`。異常 IPC の不正応答は `Plugin`。外部呼出しリトライに伴う重複書込み対策は V2。
